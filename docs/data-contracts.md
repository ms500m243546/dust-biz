# Data Contracts

Schemas for every piece of data that crosses a subsystem boundary.

These shapes are the source of truth. Pydantic schemas in
`app/schemas/` (Phase B onward) implement them. Database tables in
`app/storage/` materialize them. The dashboard consumes them.

A change to any field here is a contract change and triggers the
architect protocol.

---

## Conventions

- Timestamps: ISO 8601 UTC strings (`"2026-04-30T14:32:00Z"`).
- IDs: human-readable when generated by humans (`"Haul_Road_C"`),
  prefixed when generated by the system (`"REC-20260430-00192"`).
- Confidence: float in `[0.0, 1.0]`.
- Nullability: only fields explicitly marked `optional` may be null.
- Versioning: `model_version`, `feature_pipeline_version` are required
  on every record they apply to.

## Entity catalog (Phase B/C onward)

### `mines`
- `mine_id` (string, PK)
- `name` (string)
- `default_automation_level` (enum: L0..L4)
- `default_risk_thresholds` (JSON: `pm10_warning`, `pm10_breach`,
  `pm25_warning`, `pm25_breach`)
- `created_at`, `updated_at`

### `zones`
- `zone_id` (string, PK)
- `mine_id` (FK)
- `zone_type` (enum: `pit`, `haul_road`, `stockpile`, `dump`, `crusher`,
  `loading_area`, `boundary`)
- `geometry` (GeoJSON; optional in MVP)
- `operational_importance` (enum: `low`, `medium`, `high`, `critical`)
- `dust_generation_baseline` (enum: `low`, `medium`, `high`)
- `allowed_interventions` (array of intervention_id)
- `requires_approval_for` (array of intervention_id)

### `sensors`
- `sensor_id` (string, PK)
- `mine_id` (FK)
- `zone_id` (FK, optional)
- `sensor_type` (enum: `pm10`, `pm25`, `pm1`, `wind`, `humidity`,
  `temperature`, `pressure`, `rainfall`, `solar`, `visibility`,
  `multi`)
- `location` (lat/lon/elevation; optional)
- `is_compliance_station` (bool)
- `installed_at`, `decommissioned_at` (optional)

### `sensor_readings` (immutable, raw)
- `reading_id` (PK)
- `sensor_id` (FK)
- `timestamp` (UTC)
- `raw_value` (JSON; sensor-specific)
- `received_at` (UTC)
- `source_quality_hint` (optional float; from sensor itself)

### `weather_readings` (immutable, raw)
- `reading_id` (PK)
- `source` (string; e.g. on-site station ID, external API name)
- `zone_id` (FK, optional)
- `timestamp` (UTC)
- `wind_speed_ms` (float, optional)
- `wind_direction_deg` (float, optional)
- `gust_speed_ms` (float, optional)
- `humidity_pct` (float, optional)
- `temperature_c` (float, optional)
- `pressure_hpa` (float, optional)
- `rainfall_mm_15min` (float, optional)
- `solar_wm2` (float, optional)
- `visibility_m` (float, optional)

### `equipment`
- `equipment_id` (PK)
- `mine_id` (FK)
- `equipment_type` (enum: `truck`, `shovel`, `crusher`, `drill`,

### `equipment_activity` (immutable, raw)
- `activity_id` (PK)
- `equipment_id` (FK)
- `timestamp` (UTC)
- `zone_id` (FK, optional)
- `activity_type` (enum: `idle`, `loading`, `hauling`, `dumping`,
  `drilling`, `crushing`, `watering`, `grading`, `maintenance`,
  `other`)
- `speed_kmh` (float, optional)
- `tonnage` (float, optional)
- `raw_payload` (JSON; original record from dispatch / GPS)

### `haul_road_segments`
- `segment_id` (PK)
- `mine_id` (FK)
- `from_node`, `to_node` (zone references)
- `length_m` (float)

- `metric_id` (PK)

## Wire-format examples

The examples in `docs/subsystem-contracts.md` (S1-S16) are the
canonical wire formats for each subsystem boundary. The schemas above
are the persistence and contract specifications.

If the wire format and the schema disagree, the schema wins and the
wire format is updated.

---

## Separation rules (enforced)

- Raw readings (`sensor_readings`, `weather_readings`,
  `equipment_activity`) are **never overwritten or deleted**.
- Derived data (features, predictions, attributions, simulations,
  recommendations) lives in separate tables.
- Predictions are never updated post-issue; outcomes go in
  `action_outcomes`.
- Approvals reference recommendations; recommendations are immutable
  once issued.
- Audit logs are append-only.
